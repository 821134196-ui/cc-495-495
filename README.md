# 实习三方协议管理系统

学校为学生登记实习单位、岗位、指导老师、实习周期与三方协议版本的本地演示系统。
纯 Python 标准库实现（`http.server` + `sqlite3`），零第三方依赖。

## 启动（一条命令）

```bash
python3 app.py
```

打开 http://127.0.0.1:8000 。首次启动自动建库并写入演示数据，**包含撤岗样例**：
周雨（计算机学院）在星图科技的「前端开发实习生」协议生效后，单位撤岗，
经学生与学院确认后 v1 失效、v2 登记终止，实习天数截断至 2026-09-30（92 天），
在「变更对比」「协议归档」页可直接查看完整版本链。

端口可用环境变量覆盖：`PORT=8080 python3 app.py`。

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖四组关键场景（24 个用例）：

| 场景 | 文件 | 验证点 |
| --- | --- | --- |
| 签署顺序 | `tests/test_signing_order.py` | 乱序签署 409 并记录 `order_error` 事件；顺序 学生→学院→单位 走通后生效 |
| 旧版失效 | `tests/test_version_chain.py` | 变更生效后旧版本 `superseded` 不能再签；撤岗/提前结束截断天数且连续可查；附件版本号递增 |
| 跨学院隔离 | `tests/test_isolation.py` | 老师审外学院 403；学生代单位确认 403；外单位联系人不可操作；待办按学院隔离 |
| 并发审批 | `tests/test_concurrency.py` | 两审核人同时审核/签署/确认只有一个成功；旧版本绝不重新生效（唯一部分索引兜底） |

## 功能与页面

- **岗位申请**：学生提交岗位信息 → 学院核对培养要求 → 单位联系人确认职责，随后自动生成三方协议 v1。
- **三方签署**：进度页按学生、学院、单位三方并列展示签署状态（签署人、时间、模拟签名哈希），顺序错误会被拒绝并留痕。
- **变更对比**：已生效协议可发起撤岗 / 转岗 / 提前结束 / 联系人更换 / 附件更正；受影响方重新确认后生效；页面并排展示岗位与日期等字段差异，并显示实习天数分段与连续性。
- **老师待办**：本学院的待审申请、待学院签署、待确认变更（跨学院不可见不可审）。
- **协议归档**：每个申请的版本链（v1、v2…，附件 A1、A2…）与全部事件时间线；协议全文在独立面板查看，不塞进小卡片。

界面以白、深灰为主，校园蓝点缀。

## 存储与适配器

- `data/app.db`（SQLite）：签署记录、协议版本、变更单、天数分段、事件链、通知。
- `data/agreements/`：虚构协议文件，文件名含版本号（如 `AG-0002-v2-A1.md`）。
- `data/notifications.log`：模拟通知网关输出。
- 签名与通知均走 `adapters.py` 中的模拟适配器，不触网。

## 关键规则实现位置

- 签署顺序 / 学生不能代单位确认：`services.py` 的 `sign_agreement`、`_authorize_party`。
- 老师只能审核本学院：`college_review` 及所有学院方校验。
- 并发不让旧版本复活：`db.py` 唯一部分索引 `one_effective_per_application` + 全部条件更新（`UPDATE … WHERE status=旧值`）+ `BEGIN IMMEDIATE` 事务。
- 实习天数连续可查：`day_segments` 分段，变更生效时截断/续接，`GET /api/students/{id}/days` 返回分段、合计与连续性校验。
- 版本链留痕：`agreements.prev_id` 串联版本，`events` 表记录撤岗、转岗、提前结束、签署顺序错误、联系人更换、附件不一致等全部事件。
